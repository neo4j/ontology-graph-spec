= Migration
:description: Convert models between the Neo4j Ontology Graph Specification and Aura Data Importer formats.

Migration converts models between this specification and the Aura Data Importer formats, in as many steps as needed.

[cols="1,3,2,1"]
|===
| Type | Format | Read | Write

| `graph_spec` | This specification | 1.0.0, 1.1.0 | 1.1.0
| `data_model` | Aura Data Importer graph data model | 2.3.0, 2.4.0, 3.0.0 | 3.0.0
| `data_model_wrapped` | Aura Data Importer model file, which wraps the data model with user interface
information | 2.3.0, 2.4.0, 3.0.0 | 3.0.0
|===

The version of a document is read from the document: from the `schema` URL for this specification, and from the data
model's `version` field for the Aura Data Importer formats.

== Fields carried to and from the data model

Data model `3.0.0` carries these fields, and they are preserved in both directions:

* `description`, `aliases` and `reference` on node object types, relationship object types and properties.
* `count`, `minCount` and `maxCount` on the `from` and `to` references of a relationship object type, which map to
`count`, `min_count` and `max_count` on the `from` and `to` ends of a relationship.
* `pattern` and `one_of` on properties.

== C#/.NET

[source,csharp]
----
using Neo4j.OntologyGraphSpec;

var model = GraphSpec.Json.DecodeFromString(importerJson, ModelType.DataModel);
var output = GraphSpec.Json.EncodeToString(model, ModelType.DataModelWrapped, "3.0.0");
----

Use `GraphSpec.Yaml` for YAML input or output. The same shared migration code runs on all supported .NET platforms.
Unsupported versions/types fail with `GraphSpecException`. Data Importer output requires explicit relationship
endpoint nodes and complete foreign-key references; not every valid graph spec model can be exported. Arbitrary
custom metadata is not carried into that format. The shared migration fixtures cover supported routes and these
limitations; a round trip is not guaranteed to preserve every field.
